핵심 직관: 결정 트리는 “질문표”를 만든다

결정 트리는 데이터에 대해 하나의 큰 공식을 만드는 대신, 질문을 순서대로 던지는 구조를 만듭니다. “이 특성값이 기준보다 작은가?”, “그렇다면 왼쪽으로, 아니면 오른쪽으로” 같은 식입니다.

분류 문제에서 트리는 마치 상담원이 체크리스트를 따라가는 방식과 비슷합니다. 처음부터 모든 조건을 동시에 보지 않습니다. 먼저 가장 도움이 되는 질문 하나를 고르고, 그 질문의 답에 따라 데이터를 둘로 나눕니다. 그리고 나뉜 각 부분에서 다시 다음 질문을 고릅니다. 이렇게 반복하면 루트(root)에서 시작해 잎(leaf)으로 내려가는 의사결정 경로가 만들어집니다.

교재에서 강조하는 결정 트리의 핵심은 이 재귀적 분할입니다. 각 노드는 하나의 테스트를 담고 있고, 각 테스트는 현재 보고 있는 데이터의 일부를 한 특성 축을 기준으로 둘로 나눕니다. 따라서 결정 트리는 데이터 공간을 여러 직사각형 영역으로 잘라내는 모델이라고 볼 수 있습니다.

발표용 한 문장: 결정 트리는 데이터를 한 번에 분류하는 공식이 아니라, 좋은 질문을 하나씩 쌓아 최종 판단으로 내려가는 질문 지도입니다.
Node

질문

예: x[0] ≤ 0.52? 처럼 하나의 특성과 기준값으로 데이터를 나눕니다.

Branch

답에 따른 이동

질문이 참이면 왼쪽, 거짓이면 오른쪽으로 이동합니다. 이동 자체가 조건문의 흐름입니다.

Leaf

최종 예측

도착한 잎에 들어 있는 훈련 샘플의 다수 클래스 또는 평균값으로 예측합니다.

02 / 07

분할: 하나의 질문이 공간을 둘로 자른다

결정 트리의 각 질문은 한 특성만 봅니다. 그래서 2차원 그림에서는 수직선 또는 수평선 하나가 생깁니다. 이것이 선형 모델의 기울어진 직선 경계와 다른 중요한 특징입니다.

아래 데모는 교재의 forge 데이터셋 설명을 단순화한 예시입니다. 버튼으로 기준 특성을 바꾸고, 슬라이더로 임계값을 움직여보면 질문 하나가 데이터 공간을 어떻게 둘로 나누는지 확인할 수 있습니다. 이 단계에서는 아직 완성된 트리가 아닙니다. 단지 “노드 하나가 하는 일”만 분리해 보여주는 것입니다.

선을 움직이면 양쪽 영역의 클래스 섞임 정도가 바뀝니다. 좋은 질문은 한쪽에 비슷한 클래스가 많이 모이게 만듭니다.

관찰 포인트

  • 질문 하나는 한 특성 축에 평행한 경계를 만듭니다.
  • 분할 뒤 양쪽 영역이 한 클래스에 가까워질수록 좋은 분할입니다.
  • 트리는 이 과정을 각 영역에서 다시 반복합니다.

교재 연결

교재는 각 테스트가 현재 고려하는 데이터 일부를 하나의 축을 따라 나누며, 반복된 분할이 계층적인 partition을 만든다고 설명합니다. 그래서 결정 트리의 경계는 축에 평행한 직선들의 조합이 됩니다.

발표 포인트: 결정 트리는 “가장 좋은 질문을 하나 고르고 → 나뉜 데이터에서 다시 좋은 질문을 고르는” 과정을 반복합니다. 그래서 트리의 구조는 질문의 순서이고, 결정 경계는 그 질문들이 남긴 칼자국입니다.
03 / 07

깊어질수록 경계는 계단처럼 세밀해진다

선형 모델의 결정 경계가 하나의 직선이라면, 결정 트리의 결정 경계는 여러 개의 수직선과 수평선이 만든 계단형 영역입니다. 깊이가 커질수록 더 많은 질문을 던지고, 공간은 더 잘게 쪼개집니다.

아래 데모는 간단한 greedy tree를 브라우저 안에서 직접 학습합니다. max_depth를 바꾸면 같은 데이터에 대해 트리가 얼마나 깊게 자라는지, 그리고 경계가 얼마나 복잡해지는지 볼 수 있습니다. 깊이 1에서는 질문 하나만 허용됩니다. 깊이 4 이상에서는 작은 예외점 주변까지 따라가며 영역이 복잡해집니다.

깊이 1

깊은 트리

질문을 계속 던져 작은 영역까지 나눕니다. 훈련 정확도는 올라가지만, 이상치 하나를 위한 작은 영역이 생길 수 있습니다.

순수 잎

잎 안의 데이터가 모두 같은 클래스라면 pure leaf입니다. 모든 잎을 순수하게 만들 때까지 자라면 훈련 세트를 거의 외운 상태가 됩니다.

04 / 07

복잡도 제어: 트리가 너무 자라지 못하게 막기

트리를 끝까지 자라게 두면 훈련 데이터에 매우 잘 맞습니다. 문제는 그 성능이 새 데이터로 이어지지 않을 수 있다는 점입니다. 교재는 이를 결정 트리의 대표적인 과적합 위험으로 설명합니다.

과적합을 줄이기 위한 방법은 크게 두 방향입니다. 하나는 트리가 완전히 자라기 전에 멈추는 pre-pruning입니다. 다른 하나는 일단 크게 만든 뒤 정보가 적은 노드를 제거하는 post-pruning입니다. 교재 기준으로 scikit-learn의 결정 트리는 pre-pruning을 사용합니다.

깊이를 키우면 훈련 정확도는 쉽게 올라갑니다. min_samples_leaf를 키우면 작은 예외 영역이 줄어듭니다.

대표 제어 장치

  • max_depth: 트리의 최대 깊이를 제한합니다.
  • max_leaf_nodes: 잎 노드 수를 제한합니다.
  • min_samples_leaf: 잎에 최소 몇 개의 샘플이 있어야 하는지 제한합니다.

발표 멘트

“결정 트리는 질문을 많이 할수록 훈련 데이터를 더 잘 맞힙니다. 하지만 좋은 모델은 모든 질문을 끝까지 하는 모델이 아니라, 새 데이터에도 통할 만큼만 질문하는 모델입니다.”

from sklearn.tree import DecisionTreeClassifier
from sklearn.model_selection import train_test_split

X_train, X_test, y_train, y_test = train_test_split(
    cancer.data, cancer.target, stratify=cancer.target, random_state=42)

tree = DecisionTreeClassifier(max_depth=4, random_state=0)
tree.fit(X_train, y_train)

print("Training accuracy:", tree.score(X_train, y_train))
print("Test accuracy:", tree.score(X_test, y_test))
주의: 트리가 깊어질수록 “설명할 수 있는 구조”라는 장점도 약해집니다. 작은 트리는 사람이 읽을 수 있지만, 큰 트리는 분기 수가 너무 많아져 시각화해도 이해하기 어렵습니다.

회귀 트리: 숫자는 잎의 평균으로 예측한다

결정 트리는 분류뿐 아니라 회귀에도 사용할 수 있습니다. 회귀 트리에서도 경로를 따라 잎까지 내려가는 과정은 같습니다. 차이는 잎에서 다수 클래스를 고르는 대신, 그 잎에 들어 있는 훈련 타깃값의 평균을 예측한다는 점입니다.

아래 데모에서 깊이를 올리면 예측 곡선이 점점 계단처럼 세밀해집니다. 선형 회귀처럼 범위 밖으로 쭉 뻗어 나가는 직선을 만들지 않습니다. 트리 기반 회귀 모델은 훈련 데이터 범위 밖에서 새로운 추세를 외삽하지 못하고, 마지막으로 본 영역의 값을 계속 예측하는 성질이 있습니다.

분류와 같은 점

질문을 따라 내려가 잎을 찾습니다. 각 질문은 여전히 하나의 특성 기준입니다.

분류와 다른 점

분류는 잎의 다수 클래스를 예측합니다. 회귀는 잎에 들어 있는 타깃값들의 평균을 예측합니다.

한계

트리 회귀는 훈련 범위 밖의 새로운 추세를 만들어내지 못합니다. 관측한 구간을 나누고, 각 구간의 값을 기억하는 방식에 가깝습니다.

06 / 07

특성 중요도: 어떤 질문이 많이 기여했는가?

결정 트리는 어떤 특성이 분할에 얼마나 많이 기여했는지 feature importance로 보여줄 수 있습니다. 이 값은 모델 해석에 도움이 됩니다. 다만 이 값 하나만 보고 “그 특성이 높으면 반드시 어느 클래스다”라고 해석하면 안 됩니다.

교재는 Breast Cancer 데이터셋의 결정 트리에서 worst radius가 매우 중요한 특성으로 나타나는 예를 보여줍니다. 그러나 중요도가 낮다고 해서 그 특성이 정보가 없다는 뜻은 아닙니다. 다른 특성이 같은 정보를 이미 담고 있어서 선택되지 않았을 수도 있습니다. 또한 중요도는 항상 양수이고, 어느 클래스 방향으로 작용하는지는 알려주지 않습니다.

막대는 단순화된 예시입니다. 중요한 특성은 자주, 또는 좋은 위치에서 분할에 쓰인 특성으로 이해하면 됩니다.

좋은 해석

“이 트리는 이 특성을 분할에 많이 사용했고, 그만큼 예측에 기여했다.”

위험한 해석

“이 특성이 크면 반드시 Class 1이다.” 중요도는 방향을 말해주지 않습니다. 선형 모델의 계수와 다르게 부호도 없습니다.

상관된 특성

비슷한 정보를 담은 특성이 여러 개 있으면, 트리는 그중 하나만 골라 쓸 수 있습니다. 그러면 나머지 특성의 중요도는 낮게 보일 수 있습니다.

정리: 읽기 쉬운 모델이지만, 쉽게 과적합된다

결정 트리의 매력은 명확합니다. 모델이 질문의 형태로 표현되므로 작은 트리는 비전문가도 읽을 수 있습니다. 또한 각 특성을 따로 처리하므로 특성 스케일이 달라도 표준화나 정규화가 거의 필요 없습니다.

하지만 단일 결정 트리는 과적합되기 쉽습니다. pre-pruning을 해도 일반화 성능이 충분히 좋지 않을 수 있습니다. 그래서 교재는 바로 다음 절에서 여러 결정 트리를 결합하는 앙상블, 특히 Random Forest와 Gradient Boosted Decision Trees로 넘어갑니다.

장점 1작은 트리는 구조를 시각화하고 설명하기 쉽습니다.
장점 2스케일에 민감하지 않아 전처리 부담이 낮습니다.
약점 1깊게 자라면 훈련 데이터를 외우기 쉽습니다.
약점 2단일 트리보다 앙상블 트리가 실전에서 더 자주 쓰입니다.
from sklearn.tree import DecisionTreeClassifier

tree = DecisionTreeClassifier(
    max_depth=4,
    min_samples_leaf=3,
    random_state=0
)

tree.fit(X_train, y_train)

print(tree.score(X_train, y_train))
print(tree.score(X_test, y_test))
print(tree.feature_importances_)
최종 발표 문장: 결정 트리는 질문을 쌓아 데이터 공간을 자르는 모델입니다. 이해하기 쉽고 전처리에 강하지만, 너무 깊게 자라면 훈련 데이터를 외우므로 반드시 복잡도 제어를 함께 생각해야 합니다.
다음 절 예고: 단일 결정 트리의 과적합 문제를 줄이기 위해 여러 트리를 결합하는 방법이 등장합니다. 그것이 바로 Random Forest와 Gradient Boosted Decision Trees입니다.
